# Qwen3-TTS Studio — Design and UX QA

**Version:** 0.1 · **Status:** Proposed checks, not executed tests

Use this checklist for the initial Create Voice redesign pull request. Mark each item **PASS / FAIL / N/A**, record screenshots and the tested platform, and leave a reason for every N/A.

## 1. Scope / regression

- [ ] Changes stay within the approved UI scope; no unreviewed inference or audio format changes.
- [ ] Existing VoiceDesign generation remains reachable and produces an audible output.
- [ ] VoiceClone, My Voices and Audiobooks remain reachable and do not regress.
- [ ] Existing save paths, output conventions, identifiers and model cache continue to work.
- [ ] Any unsupported feature shown in a mockup is not presented as working in the actual UI.
- [ ] No cache, generated audio, local environment or credentials are committed.

## 2. Visual hierarchy

- [ ] Selected `Create Voice` nav item uses a neutral/subtle selected treatment.
- [ ] Exactly one strongly emphasized orange action is visible for the current task: `Generate voice`.
- [ ] No gradients or skeuomorphic/glass visual treatments.
- [ ] Input and preview use compact, consistent spacing and radii.
- [ ] Default input outline is neutral; focus and error states are distinct.
- [ ] Text and control labels do not clip at tested window sizes.
- [ ] Visual review includes idle, busy, ready and error states—not only a polished success screenshot.

## 3. Behavioral flow

- [ ] First-time user can find where to describe a voice without explanation.
- [ ] Description is preserved through waiting, generation, failures and retry.
- [ ] Users can distinguish the navigation destination from the generation action.
- [ ] Downloading, loading and generating have meaningfully different copy where the backend permits.
- [ ] No fake duration, percentage, waveform, or readiness state is displayed.
- [ ] Save/Download are only actionable when a real output is available.
- [ ] Regenerate behavior is clear; prior output is not discarded without an intentional product decision.
- [ ] Technical details are discoverable but not required for the normal happy path.
- [ ] Unsupported backend combinations either cannot be selected or fail with recoverable guidance.

## 4. Accessibility

- [ ] Keyboard-only navigation reaches and operates every interactive control.
- [ ] Tab order follows the visual task order; focus remains visible.
- [ ] Labels are persistent; placeholder-only inputs are not used.
- [ ] Icon-only buttons have accessible names/tooltips and meaningful states.
- [ ] Color is not the sole way to communicate selection, failure, readiness or progress.
- [ ] Text contrast and focus contrast are tested against WCAG 2.2 AA targets where applicable.
- [ ] OS zoom/font scaling is checked (including 125–200% where supported).
- [ ] Screen-reader checks cover core fields, generation status and playback controls on target platforms.

## 5. Desktop behaviors

- [ ] App launches and opens Create Voice without Python tracebacks.
- [ ] Window resizing does not overlap buttons, fields or preview.
- [ ] Long descriptions and translated labels wrap or scroll gracefully.
- [ ] If a task runs in the background, UI remains responsive.
- [ ] Repeated clicks on Generate do not start duplicate jobs.
- [ ] Closing the window during download or generation behaves safely.
- [ ] Files generated by the app can be found and opened.

## 6. Device matrix / practical test cases

| Scenario | Expected observation | Result |
| --- | --- | --- |
| macOS Apple Silicon, CPU + compatible attention | First-run model download and subsequent local loading are distinguishable | Not tested |
| macOS Apple Silicon, unsupported flash_attention_2 | An actionable compatibility error; no misleading recommendation to install CUDA packages | Not tested |
| macOS Apple Silicon, MPS selected (only if added later) | Real inference works, or explicit unsupported state; no false `Auto` claim | Not in initial scope |
| Windows + NVIDIA / supported setup | Existing generation and save path remain functional | Not tested |
| Narrow desktop window | Core actions readable without overlap | Not tested |
| Keyboard-only | Full first-sample journey possible | Not tested |

## 7. Suggested user test

Tasks: (1) Create a friendly narrator; (2) revise and audition an alternative; (3) find advanced attention settings. Record task completion, misclicks, assistance, and first-audio time separated into download/load/generation. Do not claim success metrics before testing.

## 8. Pull request evidence

Include: purpose and non-goals, before/after screenshots at the same dimensions, UI states, tested OS/Qt/Python versions, commands executed, checklist results, known limitations, and links to relevant design docs. Explain whether the PR changes appearance only or behavior too.

## Ship decision

- **GO:** core flow, accessibility, and regression checks passed; no known high-impact blocker.
- **GO with conditions:** minor documented issues have owner and follow-up; no data loss or broken main flow.
- **NO-GO:** main journey fails, controls mislead, state claims are fake, regression affects saving/generation, or serious accessibility blocker remains.
